---
name: new-maestro-test
description: Write a new Nimiq Pay Maestro flow for a feature, have the maestro-test-critic agent review it adversarially (including a negative-control run), prove it locally, and add it to the BrowserStack suite in quarantine. Use for "add a Maestro test for X" or "cover X with an e2e test".
argument-hint: <feature or user journey to cover>
---

Cover `$ARGUMENTS` with a new Maestro flow.

1. **Learn the conventions and the UI.** Read `nimiq-pay-tests/CLAUDE.md` and `nimiq-pay-tests/pageObjects/android/mainFlowsAndroid.page.js`. Find the feature's components in `src/` and note which elements Maestro can see (text, `aria-label`, HTML `id`; not `data-testid`). App source changes are out of scope: if the feature has no usable selector, stop and tell the human.
2. **Explore on a device.** `mcp__maestro__list_devices`, then walk the journey with `inspect_screen` and inline `run` YAML. Copy selector text verbatim from `inspect_screen`; never author it from a screenshot or from memory.
3. **Write the flow** at `nimiq-pay-tests/flows/francisco_tests/<name>.yaml`: header `appId: ${APP_ID}`, tags `franciscoTest` and `quarantine`, then the page objects and `../../subflows/create_account.yaml`. Add new selectors to the page objects. Assert the result of the journey, not just its screens. Flows that need funds don't tap the faucet (it allows about 3 taps per 12 h): they start with `launchApp: clearState: true`, import the shared funded testnet wallet with `subflows/import_wallet.yaml` (`RECOVERY_PHRASE: ${MAESTRO_TESTNET_WALLET_WORDS}`), switch with `subflows/switch_to_testnet.yaml`, and add the tag `needsTestnetWallet` (see `withdraw_nim_testnet.yaml`). Run them locally through `scripts/maestro-local.sh` with `-e DEV_MODAL_HOLD_DEVICE=Pixel_8` on the Pixel_8 AVD.
4. **Prove it locally:** `maestro check-syntax <flow>`, then `maestro --device <id> test -e APP_ID=com.nimiq.pay.debug -e PIN=1111 <flow>` until it passes three times in a row.
5. **Adversarial review.** Run the `maestro-test-critic` agent with the flow path. Fix every finding and rerun the critic until it returns APPROVE, at most three rounds; then ask the human. Never mark a flow done without the critic's negative control.
6. **BrowserStack.** Ask the human before spending a session. If approved: `node scripts/browserstack-maestro-run.js --app NimiqPayAndroidApkDebug --suite francisco_tests --device "Samsung Galaxy S26-16.0" --flow flows/francisco_tests/<name>.yaml --env APP_ID=com.nimiq.pay.debug --env PIN=1111 --maestro-version 2.6.1 --output maestro-reports/<name>`; for `needsTestnetWallet` flows add `--secret-env MAESTRO_TESTNET_WALLET_WORDS --env "DEV_MODAL_HOLD_DEVICE=Samsung Galaxy S26-16.0"`. The suite zip must contain the new flow, so upload the suite first (`node scripts/browserstack-maestro-upload.js --custom-id <your-own-id>`, never `francisco_tests`, which CI owns).
7. **Report:** the flow path, what it proves, the critic's verdict and negative control, local runs, and the BrowserStack result. Remind the human that the flow stays tagged `quarantine` (runs in CI without failing it) until it has passed 2 suite runs in a row; promoting it means removing the tag.
